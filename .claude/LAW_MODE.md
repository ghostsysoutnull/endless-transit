# Law mode

A session that works on the rules themselves, not the product. It runs only when the user says "law mode".

1. **Target.** I read the rules the user names with what refers to them and what they refer to.
2. **Where a rule lives.** The more general a rule, the wider the place that loads it: the most general carry no
   example and no history; the specific live closer to what they govern; detail lives in docs read on demand.
3. **The moves.** What I look for, and what each becomes:
   - a tour of classes → a map of where each new kind of thing goes; the tour moves to a doc read on demand;
   - a project example inside a general rule → moved down to the codebase's rules; the general rule keeps the
     principle;
   - a date, an iteration tag or an incident inside a rule → removed; the history lives in the records;
   - a rule copied from another file → a pointer to its owner;
   - a check that lists the rules it enforces → a pointer to the file that owns the list;
   - a reference to a rule by its number → the rule's words;
   - tool and file names inside a process → their roles;
   - a handover that has grown rules → state and pointers only, under a smaller cap;
   - a list of principles written from memory → checked against the people who first stated them; the file keeps the
     rule, the chat gets the sources;
   - a rule doing two jobs → split; a rule contradicting another or the code → one wins; a rule nothing guards → said
     so.
4. **Limits.** Only rules and docs change, never the product or its tests; a subagent, when there is one, is
   read-only.
5. **After every rewrite.** A script shows that no name was lost; a search finds every reference the change made false.

Everything in the Codex still holds, under the user block at the top of `CLAUDE.md`.
