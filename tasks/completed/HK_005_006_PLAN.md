## HK-005 — `Container.populateChildren()` dispatches through the registry

### What changes (ELI5)
Thirteen location classes each carry an identical one-line method that says "factory, fill me in" while naming their
own specific factory method. One shared default in `Container` asks the registry instead; the registry already knows
which factory owns which class (`ProceduralFactory.populate(Container)`, Phase 9o). The thirteen overrides and their
thirteen `ProceduralFactory` imports go away (except `Building`, which still uses the facade for `createFloor` and
`countSubLocations`). Twelve facade `populateX` delegators then have no caller and are deleted. `populateApartment`
keeps two test callers (`ObjectDistributionTest:22`, `ProcgenVariabilityTest:29`) and stays — user rule (option 3a
fallback) — logged as a follow-up.

**Behavioral edge (declared):** a `Container` subclass with **no** registered factory used to stay silently empty; after
this change its first lazy access throws `IllegalStateException("No LocationFactory registered for …")`. No such class
exists in `src/main`; the only one in `src/test` (`Orphan`) never triggers lazy population. Fail-loud is the intended
contract (the registry already throws). Detail (read `LazyLocusList.groovy:22-26` + `Container.groovy:105-110`):
`ensureChildrenPopulated()` sets `childrenPopulated = true` *before* the throw, so only the **first** access throws;
a second access returns an empty list silently. **UNGUARDED** at the lazy-access level → one assertion added to
`ProceduralFactoryRegistryTest`: the first `new Orphan().getChildren().size()` throws once the default is in place
(test comment states the first-access-only semantics). Because the
assertion is only true *after* commit 1, it lands **with** commit 1 (test edits are free under the Refactor Guard), not
as a separate step-0 commit; the pre-change guard for "13 registered, dispatch exact" already exists (rows 1-2).
