## Patterns
- **Directory Structure**: Aligning with standard JVM layouts (`src/main/groovy`, `src/test/groovy`) simplifies classpath management and tool integration.
- **Compilation Gatekeeper**: Use `groovyc` in the `run.sh` script to enforce static type checking before any tests run.
- **Clinical Interface (vinc.sh)**: For agent-driven operations or automated CI, use `./vinc.sh` instead of `./run.sh`. This provides zero-latency execution, silent success, and mandatory substrate verification without the thematic intro overhead.
- **Context-Efficient Testing**: Use `./vinc.sh --test --agent 2>/dev/null` for quick gate checks (1 line: `STATUS=PASS|FAIL ...`). Use `./vinc.sh --test -q` when debugging failures (20 lines with stack frame location). `--agent` is the default for agentic verification; `-q` is for human-readable diagnosis.
- **Build Cache Staleness**: Always run `rm -rf build/vinc` after deleting or renaming any `.groovy` source file. `vinculum_compile()` never purges stale artifacts — deleted classes continue to be discovered and run until the cache is manually cleared. Symptom: test discovered count is higher than expected, or unknown tests appear in output.
- **Read the runner script before designing a loading strategy**: The test classpath is defined in `vinc.sh`, not `build.gradle` — they can diverge. Always check `vinc.sh` before assuming `getResourceAsStream()` or any classpath-based loading will work. In this project, `src/main/resources` is not on the test classpath.
- **Every execution mode in `vinc.sh` must share the same classpath**: `--test`, `--scan`, `--replay`, and the default game launch are four separate `groovy -cp ...` invocations. Adding an entry (e.g. `src/main/resources`) to one without updating the others creates a silent divergence: resources load in tests, crash at runtime. When changing any classpath entry, grep `vinc.sh` for all `groovy -cp` lines and apply the change to all of them.
- **Standalone model objects require manual property setup**: `new Building(LocusSeed)` has `maxFloors=0` by default. Tests that create model objects outside the full procgen chain must set domain properties (`culture`, `timeline`, `maxFloors`, `apartmentsPerFloor`) explicitly, or `getFloor(0)` and similar accessors return null silently.
- **`getResourceAsStream` requires an index file for directory enumeration**: Classpath resource loading cannot list directory contents — especially inside a JAR where `jar:` URIs expose no directory API. When converting any resource directory from filesystem to classpath loading, add an `index.txt` alongside the resource files listing the available keys (one per line). Load the index first, then load each named file. This pattern is portable to JARs, consistent across directories, and makes available resources explicit.
- **A golden directory needs exactly one writer**: the generator (`GoldenFrameGenerator`, `./vinc.sh --goldens`) is the only code that writes goldens; it runs on the same classpath as `--test`, deletes stale files, and stores frames pre-masked so a second regeneration is byte-identical. Tests only read. Regenerate only after an intended visual change and review `git diff` on the goldens before committing — a casual regeneration can launder a regression.
- **Gate the golden regeneration on the simulated frame set, mechanically**: `SIM=$(groovy … sim.groovy)`, then `./vinc.sh --goldens` only if `grep '^MOVED'` equals the row's list — otherwise print STOP and leave the tree for a human. The chain caught nothing at c6a/c6b (it matched) and was too strict at c6b (zero movement is inside "golden 14 only"); the human check at c4 caught 8 frames against a row that said 2–3 and stopped. Either way the regeneration never runs on an unreviewed prediction. A red demo that fails to *compile* against the previous commit (new API the pin calls) is inconclusive — demonstrate red on an assertion that needs no new API, or say so in the record. (HK-016 step 2.)
- **`STATUS=ABORTED` means production code called `System.exit` mid-suite**: `Game`'s loop catch-all calls `System.exit(1)`, so a production exception inside a loop-driven test terminates the runner before its summary. Since WF-005 the runner's shutdown hook prints `STATUS=ABORTED … LAST_STARTED=<test>` (agent) or `[VINC:ABORTED]` (other modes) instead of nothing. Rerun with `-q` to see the failures reported before the exit. A test runner must never trust that the process survives the code under test. (Phase 8.)
- **A baseline file has one writer and is reviewed like a golden**: `./vinc.sh --lint --baseline` is the only thing that writes `config/lint/baseline.xml` (same discipline as `--goldens`). A diff that *adds* an entry is a regression being laundered; the review is "removals only". Never hand-edit it.
- **When the ratchet fires on a baselined method, answer the question, not the ruler**: HK-018 added one line to `SyncManager.restore` (baselined at 64) and lint went red at 65; the first response was to put two constructor arguments on one line so the count stayed 64. Legal, recorded — and wrong: the entry exists to make whoever edits a long method decide about its size. The two acceptable answers are *extract now* (HK-013 slice 1 did, one session later: three helpers moved by script, entry removed) or *re-baseline with the reason stated in the commit*. Reformatting to the recorded length is never one of them; a line count that can be satisfied by a line break measures nothing. Length is a proxy for "one method, one job" — treat the rule as a tripwire, not a law (WF-006 evaluates a complexity metric beside it).
- **Vinculum invariants are lint rules, not tribal greps**: the "no static singleton", "no `instanceof` on a State/Factory/event", "model never touches the journal or UI", "no `new Random()` in a ViewComponent" checks that retros ran by hand are now `IllegalRegex` / `IllegalClassReference` / `IllegalPackageReference` rules in `config/lint/vinc-ruleset.groovy`. When a phase establishes a new invariant, add the rule in the same phase and prove it fires on a scratch bad file before committing.

## Mistakes/Corrections
- **Package Relocation**: When moving the entry point (`Main.groovy`), ensure it is within the package structure (`com.endlesstransit`) to avoid classpath collisions or import ambiguity.
- **Verification Protocol**: Always use the `--test` parameter when executing `./vinc.sh` for verification. Avoid manual execution for logic or UI validation that can be automated via the test suite.

## Moved from the root process lessons (2026-09-25 — Groovy-only; text unchanged)
- **Test Artifact Convention**: All files written by tests fall into two categories: (1) **transient scaffolding** — always deleted in `@AfterEach` or inline cleanup, never committed; (2) **pinned baselines** — written once with write-once semantics (`if (!file.exists())`), gitignored, refreshed by deleting and re-running. Tests must never write to `src/` or overwrite committed files. Violations pollute `git status` and erode confidence in the working tree.
- **Verify the working tree after every test run**: Run `git status --short` immediately after `./terminal/vinc.sh --test`. A clean tree confirms no test is leaking artifacts. If anything appears dirty, investigate before the next commit — artifact pollution compounds silently across sessions.
- **Code generation in tests signals a missing abstraction**: When every generated file shares the same structure with only data varying, the answer is a `@TestFactory` + data files (JSON, txt), not a template engine. Generated `.groovy` source files require compilation, pollute the source tree, and risk overwriting committed code.
- **Silent defaults on semantically meaningful values deserve a guard**: Any `?: fallback` where the fallback has a distinct domain meaning (e.g., `?: AnomalousTrace.SILENCE` masking a missing Country ancestor) should emit a log warning. Without it, hierarchy errors are invisible in production and tests.
- **Run the full suite whenever the codebase is coherent, not just before commit**: At 2.5s the full suite is fast enough that frequency is not the constraint — coherence state is. For single-file changes, run the full suite after every edit (no targeted filter needed). For multi-file migrations where intermediate states are intentionally broken (e.g. changing a field type across 5 callers), use `./terminal/vinc.sh --test ClassName --agent 2>/dev/null` as the inner loop per file until all callers are updated, then run the full suite once coherence is restored. The commit gate (full suite before every commit) is the mandatory floor, not the intended ceiling.
- **Re-pin literals by allow-list, never by hand, and let the script refuse**: for a content phase that moves pinned literals in every commit, print every pinned value from a run (`PIN key=value`) and rewrite the test with a script that takes the keys this commit *may* move and exits non-zero on any other difference. Eighteen step-3 commits re-pinned this way; the script refused once — a second pin of the same building name the plan's coverage row had listed as "must not change" — which is the exact error a hand re-pin would have laundered. Before writing a coverage row, grep the test tree for the *literal* (`grep -n '"Impenetrable Unit"' src/test`), not the method. (HK-016 step 3.)
- **Verify rule names and CLI behavior against the jar, not the plan**: the OOA plan named `NoSystemExit` (does not exist — it is `SystemExit`) and assumed a Gradle plugin on a runner that never invokes Gradle. Before planning any tool integration: list the rulesets inside the jar, run a scratchpad prototype against the real tree, and probe each behavior the design depends on (exit codes, suppression annotations, path regexes must match the *whole* path — `'.*/test/.*'`, not `'test/.*'`). The prototype found the real violation counts, one duplicate-flagged import (`UnusedImport` + `UnnecessaryGroovyImport` on the same line — dedupe before deleting), and that `lib/*` on a Java classpath never descends into `lib/lint/`.
- **An import is not a call, and a method with no caller is a regression to log, not a feature to wire**: the Phase 10 plan document said `Building` called the journal (it only imported it — 13 model classes did) and listed a `LocationEntered` event for `logDiscovery`, which has had no production caller since a March persistence commit dropped it. `grep` the *call* (`JournalManager\.`), not the symbol, before planning; when a public method turns out to be caller-less, `git log -S` it — restoring lost behavior is a behavior change with its own pin and its own decision, never a silent side effect of a refactor. (Phase 10.)
