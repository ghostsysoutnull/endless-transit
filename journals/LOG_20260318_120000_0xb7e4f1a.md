# Chronicle: Test Artifact Hygiene + Regression Harness Refactor
**Log ID:** 0xb7e4f1a
**Date:** 2026-03-18

---

## Summary
A full audit of test-generated files revealed three categories of pollution: transient
artifacts not gitignored, a "living" baseline overwritten on every run, and a code
generator writing `.groovy` files into the source tree. All three were resolved
incrementally. The regression harness was redesigned around `@TestFactory` + JSON
snapshot data files, eliminating code generation entirely. Suite counts unchanged
throughout. Working tree is now clean after every `./vinc.sh --test` run.

---

## What Was Done

### Gitignore audit — transient artifacts
`baseline_refactor_survival.txt` and `temp_test_screenshot.txt` were being generated
by tests on every run but weren't gitignored. Both added to `.gitignore`; the previously
committed baseline file was untracked with `git rm --cached`.

**Commits:** `dc171ca`

### CaptureVerificationTest — surgical cleanup
`setUp()` called `dir.deleteDir()` on the entire `screenshots/` folder, which nuked
`PHASE_0_BASELINES.md` (a committed reference doc) on every run. Fixed to delete only
`screenshot_*.txt` files, leaving the rest of the directory intact.

**Commit:** `d052906`

### VisualBaselinePinningTest — write-once semantics
The test unconditionally overwrote `baseline_refactor_survival.txt` on every run
(only the timestamp changed, but it always dirtied the working tree). Changed to
write-once: the file is only created if absent. To refresh: delete and re-run.

**Commit:** `ff5e4d2`

### ReplayServiceTest — temp name + cleanup
The test was promoting a screenshot to `AutomatedRegressionTest.groovy` — a committed
file — on every run, silently overwriting it with an identical copy. Changed to use
`ReplayServiceTest_tmp` as the promotion target and unconditionally delete it on cleanup.

**Commit:** `d5ae964`

### Infrastructure lessons — two conventions codified
Added to `tasks/lessons/infrastructure.md`:
- Test artifacts are either transient (always cleaned up) or write-once baselines
  (gitignored, never overwrite committed files)
- Polling loops replace fixed sleeps for async side-effects

**Commit:** `33b59f1`

### Regression harness — @TestFactory + JSON snapshots
Root insight: every generated regression test is identical structure, different data.
`ReplayService.promoteToTest()` was generating `.groovy` source files — solving a
data problem with code generation. Redesigned:

- `RegressionHarnessTest.groovy` uses `@TestFactory` to discover all `snapshots/*.json`
  files and create one `DynamicTest` per entry
- `ReplayService.promoteToTest()` now writes a JSON snapshot instead of a Groovy class
- `AutomatedRegressionTest.groovy` (generated) deleted; its data migrated to
  `snapshots/AutomatedRegressionTest.json`
- `generateTestContent()` and the Groovy template engine removed from `ReplayService`

Adding a regression case is now: promote screenshot → JSON file written → harness
picks it up automatically. No compilation step, no source tree pollution.

**Commits:** `7548885` (backlog doc), `8aea683` (harness + migration), `2cfad2c` (ReplayService), `450d5a4` (backlog closed)

## Key Lesson
**Identify the abstraction layer mismatch.** Code generation in a test context is almost
always solving a data problem at the wrong layer. When every generated artifact is
identical structure with different values, the answer is parametrized data + a single
static runner — not a template engine.
