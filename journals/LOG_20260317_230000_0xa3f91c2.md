## Summary
Eliminated unnecessary `Thread.sleep()` calls in two test files. No production code was touched. Suite duration dropped from ~6.5s to ~2.6s — a 60% reduction.

---

## What Was Done

### Fix 1 — CaptureVerificationTest: polling loop (saved ~2.9s)
`CaptureVerificationTest.groovy` had a hardcoded `Thread.sleep(3000)` waiting for an async file write. `CaptureService.capture()` submits the write to a daemon single-thread executor; in practice the write completes in 10–50ms. The 3-second wait was pure waste.

**Fix:** Replaced the sleep with a polling loop checking for the screenshot file in 50ms increments, up to a 1000ms timeout. In practice the loop exits on the first or second iteration.

```groovy
long deadline = System.currentTimeMillis() + 1000
while (System.currentTimeMillis() < deadline) {
    if (dir.listFiles()?.length > 0) break
    Thread.sleep(50)
}
```

### Fix 2 — JournalTest: reduced sleep to 50ms (saved ~1.05s)
`JournalTest.groovy` had `Thread.sleep(1100)` to ensure `saveSession()` records a nonzero "Session Duration:". The test only asserts `content.contains("Session Duration:")` — it never checks the actual value. Any sleep > 0ms satisfies the assertion.

**Fix:** Reduced to `Thread.sleep(50)`.

## Key Lesson
**Polling beats blind sleeping.** When a test waits for an async side-effect (file write, event, state change), a polling loop with a generous timeout is strictly better than a fixed sleep: it exits as fast as possible in the common case and still catches regressions by enforcing a maximum wait.
