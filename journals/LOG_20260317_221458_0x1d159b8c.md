## What Was Done

### Phase 1a — isCorridorActive Reset Removal
`NavigationOrchestrator.enterLocation()` unconditionally reset `isCorridorActive = false` whenever a Floor was entered. During a save/restore cycle, `SyncManager` correctly applied the saved mutation state (`isCorridorActive = true`) — but the subsequent navigation call to `enterLocation()` silently overwrote it back to `false`. The save/restore of corridor state was broken.

**Fix:** Removed 5 lines from `NavigationOrchestrator.groovy` (the comment block + the conditional reset). `isCorridorActive` defaults to `false` on the field declaration — a fresh Floor naturally starts in Elevator mode. The explicit reset was the bug.

**Pre-implementation discovery:** Original OOA plan named `Floor.enter()` as the fix site. Reading the actual source confirmed the reset was in `NavigationOrchestrator.groovy:30`, not `Floor`. Plan corrected before any code was touched.

**Commit:** e8fc3bd

### Phase 1b — visitedPaths Documentation
`visitedPaths` is absent from `GameMemento` — confirmed intentional after analysis showed nothing in game logic or UI reads it. Only `visitedLIPs` drives rendering (`Building.groovy`, `Corridor.groovy`, `SessionRecap.groovy`). Added a 4-line comment to `Player.groovy` near the field declaration documenting this intentional omission so future refactors don't misread it as a bug.

**Pre-implementation discovery:** Original plan incorrectly stated `visitedLIPs` was in `GameMemento`. Grepped `GameMemento.groovy` before writing code — confirmed neither field is present. Plan corrected.

**Commit:** 0798dd2
